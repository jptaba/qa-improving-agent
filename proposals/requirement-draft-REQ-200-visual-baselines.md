# Requirement draft: REQ-200 (for a person to copy into `requirements/`)

Source: `escalations/2026-11-26T0100-visual-baselines-requirement.yml` (roadmap Phase 3, "Approval-gated visual baselines").
Agents may not write to `requirements/`, and golden rule 5 needs a requirement to tag the tests with,
so this draft waits here. To accept it, save the block below as `requirements/REQ-200-visual-baselines.md`
(edit freely) and answer the escalation. No tests or baselines exist yet; they come after the decision.

```markdown
---
id: REQ-200
title: Pages look as approved
status: in-scope
journey: Sign in, Checkout, Confirmation, Not found
---

## Acceptance criteria (EARS)
- **AC1:** THE SYSTEM SHALL render the sign-in, checkout, order confirmation and "page not found" pages so that they match their approved screenshot at a 1280×720 viewport, ignoring the order id.
- **AC2:** WHEN the look of a page changes THE SYSTEM SHALL NOT have its approved screenshot replaced unless a person approves the new one.

## Notes
- "Match" means within Playwright's default screenshot tolerance. Animations are disabled and the clock is fixed.
- Approved screenshots are taken in the CI container (Linux), not on a laptop, so fonts match the run that checks them.
```

Plan once accepted (agent work unless marked):
- Tests: `tests/visual/pages.spec.ts`, one `toHaveScreenshot` per page, tagged `@REQ-200`, order id masked.
- Baselines: generated by a manual CI run with `--update-snapshots` inside the Playwright container and
  attached as an artifact. A person downloads, reviews and commits them.
- Gate (human edit to `.github/workflows/qa.yml`): a PR that changes any `*-snapshots/*.png` fails
  unless it carries the label `visual-approved`.
- Inventory entry (human edit):

